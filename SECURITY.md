# Security Policy

## Supported Versions

| Version | Supported |
| ------- | --------- |
| latest  | Yes       |
| N-1     | Yes       |
| older   | No        |

## Reporting a Vulnerability

**Do not open a public issue for security vulnerabilities.**

Report it privately to the maintainers. Use the private reporting channel your hosting platform offers (on GitHub: the
repository's **Security** tab → **Report a vulnerability**); if it has none, contact a maintainer directly. Never post
details in a public issue or merge request. Include:

- A description of the vulnerability
- Steps to reproduce
- Potential impact
- Suggested fix (optional)

Response SLA:

- Acknowledgement within **48 hours**
- Status update within **7 days**
- Patch or mitigation within **30 days** for confirmed issues

## Out of Scope

- Vulnerabilities in third-party dependencies (report to the upstream project)
- Theoretical attacks with no practical exploit
- Issues in development-only tooling that cannot affect production
